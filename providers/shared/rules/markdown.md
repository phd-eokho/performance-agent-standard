# Markdown

- Preserve every constraint, condition, and caveat; shorten wording, never meaning.
- Generalize input into rules; keep an example only when the rule is ambiguous without it.
- No filler, greetings, or restated context.
- Structure over prose: headings, `-` for parallel items, `1.` for sequences, indentation for child scope and conditions, tables for multi-attribute data, indented pseudocode for branching procedures.
- Put identifiers, paths, and commands in backticks.
- Edit by merging into the existing document without duplication; confirm with the user before changing beyond the requested section.
- Use `> [!IMPORTANT]` blocks for boundaries indentation cannot express.
